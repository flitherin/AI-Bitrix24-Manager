# AI Bitrix24 Manager

Telegram-бот, который выступает в роли AI-менеджера входящих заявок. Он ведёт диалог с клиентом, выясняет потребность, собирает контакты и согласие на обработку данных, а затем автоматически создаёт **лид** или **сделку** в Bitrix24.

## Как это работает

1. Клиент пишет боту в личные сообщения и описывает, что ему нужно.
2. Языковая модель (OpenAI или совместимый API) ведёт диалог и задаёт уточняющие вопросы, не больше двух за раз.
3. Бот собирает анкету. Для создания заявки обязательны:
   - имя клиента;
   - потребность (товар или услуга);
   - телефон или email;
   - явное согласие на передачу данных менеджеру.

   Дополнительно собираются компания, бюджет и сроки.
4. Когда анкета заполнена и данные валидны, бот создаёт запись в Bitrix24 через входящий вебхук.
5. Если Bitrix24 временно недоступен, данные сохраняются локально, а отправку можно повторить командой `/retry` без повторного заполнения анкеты.

Выбор между лидом и сделкой: AI предлагает `deal` при конкретном намерении купить или заказать, иначе `lead`. Поведение можно зафиксировать настройкой `BITRIX24_ENTITY_MODE`. Для сделки бот сначала создаёт контакт в CRM и привязывает к нему сделку.

## Возможности

- Диалог на языке клиента (по умолчанию русский)
- Строгая валидация телефона и email, нормализация данных
- Защита от выдуманных данных: в анкету попадает только то, что клиент написал явно
- Создание лидов, контактов и сделок в Bitrix24
- В комментарии к записи попадают резюме заявки, контакты, Telegram ID и username клиента
- История диалогов и состояние заявок хранятся в SQLite
- Последовательная обработка сообщений внутри одного чата (блокировка на чат)
- **Демо-режим**: запуск без OpenAI и Bitrix24, CRM-записи выводятся в лог
- Поддержка OpenAI-совместимых провайдеров через `OPENAI_BASE_URL`
- Запуск локально или в Docker

## Команды бота

| Команда | Описание |
|---|---|
| `/start` | Приветствие или информация об уже переданной заявке |
| `/new` | Начать новую заявку (сбрасывает текущий диалог) |
| `/status` | Показать статус текущей заявки и чего не хватает |
| `/retry` | Повторить отправку в Bitrix24 после ошибки |
| `/help` | Справка |

Бот отвечает только в личных чатах.

## Стек

- Python 3.11+
- [aiogram 3](https://docs.aiogram.dev/): Telegram-бот
- [OpenAI Python SDK](https://github.com/openai/openai-python): языковая модель
- [httpx](https://www.python-httpx.org/): вызовы Bitrix24 REST API
- [aiosqlite](https://github.com/omnilib/aiosqlite): хранение данных
- [pydantic](https://docs.pydantic.dev/) и pydantic-settings: модели и конфигурация
- Docker / Docker Compose

## Быстрый старт

### 1. Клонирование

```bash
git clone https://github.com/flitherin/AI-Bitrix24-Manager.git
cd AI-Bitrix24-Manager
```

### 2. Настройка

```bash
# Linux / macOS
cp .env.example .env

# Windows (cmd)
copy .env.example .env
```

Заполните `.env`.

### 3. Запуск локально

```bash
python -m venv .venv

# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate

pip install -e .
python -m app
```

### 4. Запуск в Docker

```bash
docker compose up -d --build
docker compose logs -f
```

## Конфигурация

Все параметры задаются переменными окружения или в файле `.env`.

| Переменная | Обязательна | По умолчанию | Описание |
|---|---|---|---|
| `TELEGRAM_BOT_TOKEN` | да | | Токен бота от [@BotFather](https://t.me/BotFather) |
| `DEMO_MODE` | нет | `false` | Демо-режим без OpenAI и Bitrix24 |
| `OPENAI_API_KEY` | если `DEMO_MODE=false` | | Ключ API языковой модели |
| `OPENAI_MODEL` | нет | `gpt-4o-mini` | Модель |
| `OPENAI_BASE_URL` | нет | | Адрес OpenAI-совместимого API |
| `BITRIX24_WEBHOOK_URL` | если `DEMO_MODE=false` | | URL входящего вебхука Bitrix24 |
| `BITRIX24_ENTITY_MODE` | нет | `auto` | `auto`, `lead` или `deal` |
| `BITRIX24_DEAL_STAGE` | нет | `NEW` | Стадия создаваемой сделки |
| `BITRIX24_DEAL_CATEGORY_ID` | нет | | ID воронки для сделок |
| `BITRIX24_SOURCE_ID` | нет | | ID источника для лидов и сделок |
| `DATABASE_PATH` | нет | `data/bot.db` | Путь к файлу SQLite |
| `DIALOGUE_HISTORY_LIMIT` | нет | `12` | Сколько последних сообщений передаётся модели (2–50) |
| `REQUEST_TIMEOUT_SECONDS` | нет | `30` | Таймаут запросов к AI и Bitrix24 (до 120) |
| `LOG_LEVEL` | нет | `INFO` | Уровень логирования |

## Подключение Bitrix24

1. В Bitrix24 откройте **Разработчикам → Другое → Входящий вебхук**.
2. Выдайте вебхуку права на раздел **CRM**.
3. Скопируйте URL вебхука в `BITRIX24_WEBHOOK_URL`.

Используются методы `crm.lead.add`, `crm.contact.add` и `crm.deal.add`.

## Демо-режим

Для проверки без внешних сервисов задайте в `.env`:

```env
TELEGRAM_BOT_TOKEN=ваш_токен
DEMO_MODE=true
```

В этом режиме диалог ведёт простой rule-based алгоритм (распознаёт имя, телефон, email и согласие), а вместо Bitrix24 создаваемые лиды, контакты и сделки выводятся в лог в формате JSON. В демо-режиме нужен только токен Telegram-бота.

## Безопасность

- Файл `.env` не должен попадать в репозиторий (он указан в `.gitignore`).
- Токен бота, ключ OpenAI и URL вебхука хранятся как секреты и не логируются.
- Если секрет был опубликован, перевыпустите его.
- Заявка создаётся только после явного согласия клиента на передачу данных.

## Устранение неполадок

**`Cannot connect to host api.telegram.org:443`**: нет доступа к Telegram API из вашей сети. Проверьте соединение или используйте VPN/прокси.

**`Required when DEMO_MODE=false: OPENAI_API_KEY, BITRIX24_WEBHOOK_URL`**: заполните эти переменные или включите `DEMO_MODE=true`.

**Бот сообщает, что Bitrix24 недоступен**: данные заявки сохранены, повторите отправку командой `/retry`.
